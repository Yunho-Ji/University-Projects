> **Information**: 본 아카이브의 프로젝트들은 과거 하드웨어 손상으로 인해 소스코드는 유실되었으나, 공식 기획 및 설계 문서가 보존되어 있어 핵심 기록을 남깁니다. 당시 구축했던 관계형 데이터베이스(RDB) 설계와 JSON 파싱 경험은 현재 진행 중인 프로젝트의 정교한 데이터 아키텍처를 설계하는 강력한 기술적 뿌리가 되었습니다.

### 📝 [Record 01] 안드로이드 추천 플랫폼: 어디갈래? (2017)
> **사용자의 무의식적 선호도 데이터를 트래킹하여 여행지를 추천하는 시스템**

* **수행 기간:** 2017.03 ~ 2017.07 (4개월)
* **역할/인원:** 백엔드 API 구현 및 데이터베이스 설계 (3인 팀 프로젝트)
* **개발 환경:** `Java`, `Android Studio`, `MySQL Lite`

#### 🛠️ 담당 업무 및 핵심 구현
* **`MySQL Lite` 데이터베이스 스키마 설계:** 유저 정보, 전체 여행지 풀(Pool), 유저별 성향 데이터 간의 관계성(1:N)을 정의하고 데이터 무결성을 고려한 스키마 설계.
* **선택 기반 데이터 적재 알고리즘:** 사용자가 2지선다형 게임인 '여행지 올림픽' 콘텐츠를 진행할 때 발생하는 선택 데이터를 실시간 트래킹하고, 결과 값을 해당 유저의 고유 식별자(`UID`)에 바인딩하여 DB 세션에 영속화(`Persistence`)하는 백엔드 프로세스 구현.

### 📝 [Record 02] Full-Stack 하이브리드 플랫폼: Online Portfolio Guy (2017)
> **이종 플랫폼(Web/App) 간의 기술적 한계를 JSON 파싱으로 극복한 통합 전산화 시스템**

* **수행 기간:** 2017.08 ~ 2017.10 (3개월)
* **역할/인원:** 웹/앱 통합 백엔드 아키텍처 설계 (2인 팀 프로젝트)
* **개발 환경:** `Java (Eclipse EE)`, `JSP`, `Android Studio`, `MySQL`, `HeidiSQL`, `JSON`

#### 🛠️ 담당 업무 및 핵심 극복 과정 (Troubleshooting)
* **이종 플랫폼 간 통합 데이터 동기화:** 웹(`JSP`) 환경의 관리자 채널과 모바일(`Android`) 환경의 사용자 채널이 동일한 중앙 데이터 소스를 공유할 수 있도록 `MySQL` 중심의 테이블 정규화 및 관계 설정 수행.
* **`JSON` 파싱을 통한 외부 원격 DB 연동 돌파:**
  * **[문제]** 전 단계 프로젝트에서 로컬 임베디드 DB 수준을 넘어 외부 원격 데이터베이스와 실시간으로 데이터를 공유하고 동기화하는 구조를 구현하는 데 한계를 경험함.
  * **[해결]** 플랫폼 간 데이터 규격 불일치 문제를 해결하기 위해 표준 데이터 포맷인 **`JSON`**을 도입. 웹 서버단에서 `MySQL` 데이터를 `JSON` 스트링으로 직렬화(`Serialization`)하여 송출하는 API를 구축하고, 앱 단에서 이를 파싱(`Parsing`)하여 화면에 유기적으로 바인딩하는 외부 원격 데이터 통신 구조를 완수함.

>## 🔍 Self-Review: 과거의 나를 돌아보며

초창기 코드들을 현재의 관점에서 복기하며, 제가 얼마나 성장했는지와 앞으로 지향해야 할 엔지니어링 방향을
      정리했습니다.

#### 1. 논리 연산의 정확성 (C++)
- **Issue:** `while(start = true)`와 같이 비교(`==`)가 아닌 대입(`=`) 연산자를 사용한 실수가 있었습니다.
- **Insight:** 이제는 이런 실수가 시스템에 끼치는 치명적인 무한 루프 위험을 명확히 이해하고 있으며, 할당 연산의
      결과가 조건문에서 어떻게 평가되는지 깊이 있게 알고 있습니다.

#### 2. 데이터 구조화와 관심사 분리 (JSP/C++)
- **Issue:** `switch-case` 하드코딩이나 JSP 파일 내에 비즈니스 로직과 UI 로직이 뒤섞인 구조가 많았습니다.
- **Insight:** 유지보수와 확장을 위해서는 **관심사의 분리(Separation of Concerns)**가 필수임을 깨달았습니다.
      현재는 데이터 중심 설계와 MVC 형태의 구조적 설계를 지향합니다.

#### 3. 방어적 프로그래밍과 예외 처리 (JSP)
- **Issue:** 사용자 입력값(`prompt`)에 대한 유효성 검사 로직이 부족했습니다.
- **Insight:** "모든 외부 입력은 신뢰할 수 없다"는 전제하에 **데이터 검증(Validation)**을 최우선으로 합니다.
      이러한 마인드는 현재 Godot 프로젝트에서 데이터 직렬화 무결성을 지키는 핵심 기반이 되었습니다.
