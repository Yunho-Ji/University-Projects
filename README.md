## 📝 [Special Record] Full-Stack Web Project (with MySQL Lite)

> **Note**: 본 프로젝트는 하드웨어 손상으로 인해 소스코드가 유실되었으나, 개발자로서 데이터 아키텍처의 기반을 다진 중요한 전환점이 되었기에 핵심 설계 경험과 배운 점을 기록으로 남깁니다.

### 1. 프로젝트 개요 및 핵심 구현
* **플랫폼**: Full-Stack Web Application
* **핵심 기술**: MySQL Lite 기반 데이터베이스 설계 및 CRUD 아키텍처 구현
* **주요 작업**:
  * 관계형 데이터베이스(RDB)의 데이터 정규화 및 효율적인 스키마 설계
  * 엔티티 간의 관계성(1:N, N:M) 정의 및 데이터 무결성을 위한 트랜잭션 처리
  * 프론트엔드와 백엔드 간의 정형 데이터 통신 흐름 제어

### 2. 핵심 성과 및 핵심 역량 (Learned)
* **데이터 흐름의 시각화**: UI 단에서 발생한 이벤트가 백엔드를 거쳐 데이터베이스에 영속화(Persistence)되는 풀스택 데이터 흐름을 완벽히 이해했습니다.
* **복잡한 데이터 구조 설계 능력**: 테이블을 분하하고 인덱스를 고려하는 과정에서, 데이터 효율성과 쿼리 최적화가 시스템 퍼포먼스에 미치는 영향을 체감했습니다.

### 3. 현재 프로젝트와의 기술적 연결 고리 (Connection)
* 이때 축적된 데이터 중심 사고방식과 스키마 설계 능력은 현재 개발 중인 **다이스 던전 크롤러(DDC)** 프로젝트의 묵직한 밑바탕이 되었습니다.
* 웹 데이터베이스를 설계해 본 경험을 기반으로, DDC 내의 복잡한 **주사위 확률 데이터 시퀀싱**과 **JSON 기반 정형 데이터 구조**를 더욱 안정적으로 설계할 수 있었으며, 객체 간의 결합도를 낮추는 **시스템 매니저 구조 세분화**의 핵심 아키텍처적 영감을 제공했습니다.

>
>## 🔍 Self-Review: 과거의 나를 돌아보며

초창기 코드들을 현재의 관점에서 복기하며, 제가 얼마나 성장했는지와 앞으로 지향해야 할 엔지니어링 방향을
      정리했습니다.

#### 1. 논리 연산의 정확성 (C++)
- **Issue:** `while(start = true)`와 같이 비교(`==`)가 아닌 대입(`=`) 연산자를 사용한 실수가 있었습니다.
- **Insight:** 이제는 이런 실수가 시스템에 끼치는 치명적인 무한 루프 위험을 명확히 이해하고 있으며, 할당 연산의
      결과가 조건문에서 어떻게 평가되는지 깊이 있게 알고 있습니다.

#### 2. 데이터 구조화와 관심사 분리 (JSP/C++)
- **Issue:** `switch-case` 하드코딩이나 JSP 파일 내에 비즈니스 로직과 UI 로직이 뒤섞인 구조가 많았습니다.
- **Insight:** 유지보수와 확장을 위해서는 **관심사의 분리(Separation of Concerns)**가 필수임을 깨달았습니다.
      현재는 데이터 중심 설계와 MVC 형태의 구조적 설계를 지향합니다.

#### 3. 방어적 프로그래밍과 예외 처리 (JSP)
- **Issue:** 사용자 입력값(`prompt`)에 대한 유효성 검사 로직이 부족했습니다.
- **Insight:** "모든 외부 입력은 신뢰할 수 없다"는 전제하에 **데이터 검증(Validation)**을 최우선으로 합니다.
      이러한 마인드는 현재 Godot 프로젝트에서 데이터 직렬화 무결성을 지키는 핵심 기반이 되었습니다.
